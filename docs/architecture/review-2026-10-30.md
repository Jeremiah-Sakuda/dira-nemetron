## Scope and decisions

Recent git hotspots led the review to approved time interpretation, account transport and Calendar verification. Each pass explored the revised tree, used a read-only exploration agent, presented a fresh visual HTML report in the OS temporary directory, then implemented its recommendations. The owner selected all recommendations in advance. Existing constraints settle the design decisions: preserve the two workflow modules, authenticated approval, durable ledger state, provider identity checks, account partitioning and independent reads; add no paid infrastructure or speculative transport ports.

Dependencies vary at existing seams: production HTTP and test fetch adapters for account transport; fixture, PostgreSQL simulation and Google adapters for Calendar. In-process time derivation needs no new adapter. The new root glossary records approved intent, verification and Calendar mirror terminology. The deployment ADR records an existing substantive hosting trade-off.

## Recommendations and closure

| 3 | Concentrate complete Calendar effect read-back | Both workflow modules use one fresh-read module for CREATE/MOVE/DELETE. It checks start, end and every supplied title independently of optional adapter filters. Broker preflight reuses the same observation. All four recommendations are implemented. Each deletion concentrates actual knowledge in an existing or focused deep module. The account transport interface gives leverage to its callers; approved-time and read-back invariants gain locality across the two workflows.

## Deliberately outside this review

Merging the two workflow engines or rewriting the large persistence module would expand the interface and rollout risk before the demo without a demonstrated need. OAuth redirects, binary memory transfer and replay streams have distinct semantics and retain separate modules. No new interfaces for hypothetical providers were introduced. Existing interface tests survive because they assert observable behavior; no test-only extracted module was added.
